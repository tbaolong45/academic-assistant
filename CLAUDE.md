# Academic Assistant

Demo stage. Only the macOS app connects to a real account (Moodle); the web and Expo apps still show sample data.
- `macos/`: **the user's current priority, a fully native macOS app** (SwiftUI, Swift package, no Xcode installed). `./macos/build-app.sh` builds, runs `--self-check` (grade math) and assembles `macos/build/Academic Assistant.app` with an ad-hoc signature.
  - The Command Line Tools ship WITHOUT SwiftUI's and Swift Testing's macro plugins. So `@State` fails ("plugin for module 'SwiftUIMacros' not found"): write `@Local` (typealias in `Theme.swift`) instead. Never use `#Preview`, `@Entry` or `@Test`, which is why tests live in `SelfCheck.swift` behind the `--self-check` flag. If Xcode gets installed, switch back to `@State` and Swift Testing.
  - Moodle (`Moodle.swift`, `Keychain.swift`, `Store.swift`, `ConnectView.swift`): MBZUAI signs in through SAML SSO, so there is no password flow. The user pastes their "Moodle mobile web service" key from `{site}/user/managetoken.php`; it is stored in the Keychain only and must never reach logs, errors, the cache or stdout (`Moodle.redact`). The URLSession is `.ephemeral` so URLs carrying the key are never disk-cached. The last sync is cached at `~/Library/Application Support/AcademicAssistant/moodle-cache.json`. `--moodle-check` runs a full sync and prints counts only (exit 2 = no key stored). Field names were checked against the MOODLE_405_STABLE `*_returns()` source, not the wiki.
  - MBZUAI sign-in (verified live 2026-10-28): the account had no mobile key, and `typeoflogin=1` means `admin/tool/mobile/launch.php` only issues one right after a *fresh* login (an already-signed-in browser gets "pluginnotenabledorconfigured"). `MoodleSSO.swift` loads launch.php in its own `WKWebView` with a non-persistent store and intercepts the `moodlemobile://token=` redirect (signature = md5(wwwroot+passport)). `ASWebAuthenticationSession` showed a blank window here and crashed when its completion wasn't `@Sendable`. Don't use the QR-login API: it requires the official app's user agent.
  - Grades with unreliable weights (as of 2026-10-28, Intro to AI, Calculus and Linear Algebra items had weight 0, Python had 0/0/5, and Communication's added up to 154%): `runningGrade` uses weights only when every result has one, and otherwise takes the plain average. `doneShare` ("% done") is shown only when every weight is set and they add up to 95–105%; otherwise the UI says "no weights on Moodle". The Overview's "this week" and "next deadline" use `deadlines()`, the same sources as the board, not just gradebook items.
  - MBZUAI course shape: a lecture and its "- Lab" are separate Moodle courses with the same code ("Fall 2026/2027 Name (AI1010-001)"). `Moodle.groupCourses` merges them per code and puts trainings (HR_…, Peer_Tutoring) after credit courses. Gradebook `weightraw` is mostly 0 or category-relative, so course weights from Moodle are unreliable.
  - Download safety, from the 2026-10-28 Antigravity review: `MaterialStore.download` attaches `token=` only to https URLs on the connected Moodle host, and only writes inside `root`. `safe()` strips leading dots, so a name like ".." can't climb out of the folder. `Moodle.redact` hides both `wstoken=` and `token=`. The SSO web view allows only https/about pages.
  - Course files (`Materials.swift`): after each sync `Store` downloads missing files (Moodle `fileurl` + `token=`) to `~/Documents/Academic Assistant/<Course>/` (multi-file folders get a sub-folder; skipped if the size matches, files >300 MB skipped). The Lectures & Material rows preview with SwiftUI `.quickLookPreview` and have Open / Show in Finder / Copy path. Grade items: keep `itemtype` "mod" **and "manual"** (teachers type most quiz and exam marks by hand); drop attendance, "Mid-Term Evaluation" (a progress survey) and "Lab N Submission".
  - Deadlines/status: `core_calendar_get_action_events_by_timesort` is capped (limit 50) and fills up with attendance sessions, so it can't tell open from submitted. Use `mod_assign_get_submission_status` per assignment; with no status, an ungraded future assignment is open and a graded one is done. Truth to compare against: `{site}/mod/assign/index.php?id=<course>`. Other dated info comes from `core_calendar_get_calendar_events` (teacher events; attendance and activity events dropped), announcement bodies (`mentionedDates`, a regex parser, because NSDataDetector misses "3rd October") and syllabus/schedule PDFs (PDFKit, `MaterialStore.documentEvents`).
  - All courses are kept: credit courses get `Hue.courseHues` in order, trainings get `.slate` (never cycled). Site and personal calendar events and site news go to a "GENERAL" subject (it only exists when there's data). Every activity type except assign/forum/attendance/label is listed as a material (activities without files link to their Moodle page). Announcement dates: relative words are resolved against the post date. PDF dates use `strict: true` (number dates need a year, no relative words), drop Moodle's IP download stamps and are de-duplicated; `--doc-check` prints them from the cache (~5 s). Verified 2026-10-28: the LMS calendar Aug–Jan holds only attendance (132) and assignment due events (15), and all 15 match the app.
  - Forums: discussions from every forum are listed with announcements (31 in Communication, matching the LMS on 2026-10-28), but dates are taken only from `news` forums, so classmates' posts don't create deadlines. Grade feedback is kept per item (`Assessment.feedback`), though MBZUAI's user grade report has no feedback column, so it was empty as of 2026-10-28.
  - Deadline cards and chips open `DeadlinePreview`, a popover, instead of the course. MBZUAI assignments often have an empty Moodle description (Communication's TED Script, Slides, Final Paper and Presentation did as of 2026-10-28). The preview therefore also shows announcements that contain the title's words, and PDF passages from `MaterialStore.mentions`. Without its fixed height the popover's ScrollView collapses to 0.
  - Scenes: the `WindowGroup(id: "main")` must be the first scene in `App.body`; with `MenuBarExtra` first, macOS opens no window at launch.
  - AI classifier (the user lifted the earlier "no AI" rule on 2026-10-28 and chose TypeSafe's Jev "System One" model): `Classifier.swift` sends each announcement and dated item's text as one `choice` question (`POST https://api.typesafe.ai/v1/systemone`, `jev-latest`) over `ItemKind` (deadline, exam, class_change, event, grades, info). Answers are cached by SHA-256 of the text in `kinds.json` (owner-only), so each text costs one call. The key is in the Keychain under account `api.typesafe.ai`; the user enters it in the Connect sheet, and it is checked with one live call. "grades"/"info" events leave the deadline board, and unclassified items stay, so nothing disappears without a key. Grades and files are never sent.
  - Syllabus rules (`syllabusRules` in `Model.swift`, typed in from the course PDFs because Moodle weights these items 0): AI1110 Calculus has quizzes 30% (best 4 of 5, 7.5% each), midterm 30%, final 35% and project 5%. `withSyllabus` adds missing items as `syllabus/…` placeholders and sets `Assessment.exactWeight`, which all grade math reads through `share` (7.5 doesn't fit the Int `weight`). A placeholder in the past means awaiting a mark, never overdue.
  - Deadlines board split: `Deadline.toSubmit` (kind == .deadline: Moodle assignments and Jev "deadline") vs events. "Do next", crunch and the Overview's next-deadline tile only consider work to submit (crunch also counts exams).
  - Moodle messages (`core_message_get_conversations` + `core_message_get_conversation_messages`) and notifications (`message_popup_get_popup_notifications`) are synced as announcements (`source` .message / .notification) and routed to the course whose code or name they mention (`Moodle.route`), else to GENERAL. Dates are taken from messages but not from notifications, whose due reminders can be stale (one still said TED Script 20 Oct after it moved to 1 Nov). Scores use `exactScore` (87.5 stays 87.5). Titles of dated text items show `mainPoint()` plus the date (`Deadline.label`); the preview keeps the full sentence. Viewing other students' grades is out of scope (the user confirmed it isn't wanted).
  - Course-page text: labels (`modname == "label"`, `description`), section `summary` and activity descriptions become `Material.text` (Lectures & Material tab), and their dates are read with `strict: true`. Moodle copies the university calendar label into every course, so a course-page date found in two or more courses moves to GENERAL once. Verified 2026-10-28: Communication's assessment notes ("Critical Reading Assessment – During Lab 21st October", etc.) come through.
  - AI titles (`Summarizer.swift`, as the user specified): for each dated item on the board (from a week ago to 4 months ahead), Jev answers one yes/no (`noul`) question per sentence of its `origin` text. Up to 4 "yes" parts go to DeepSeek (`POST https://api.deepseek.com/chat/completions`, model `deepseek-flash`, key in the Keychain under account `api.deepseek.com`), which writes one title. DeepSeek is told the course and Jev type, must not name the course, must use only stated facts, and replies `SKIP` when the parts don't say what the item is. Items whose line is only a date ("Dec 8 — -", `hasContent`) are never sent or shown. Jev then checks the title with four yes/no questions: says when (≥ 0.6)? keeps the point (≥ 0.7)? specific (≥ 0.6)? invents a fact (asked as "yes = bad", rejected above 0.5, because its score is noisy and, asked positively, it punished harmless rewording)? A rejected title gets one retry, with Jev's failed checks sent back to DeepSeek as feedback (`Summary.failures`); if it fails again, the item keeps `mainPoint()`. Titles of items that no longer exist are pruned after each run. On 2026-10-28, 15 of 19 titles passed. Clicking a dated item that came from an announcement or message opens that post (`Nav.open(_:announcement:)`, `Announcement.key`), scrolled to and highlighted; other items open `DeadlinePreview`. Results are cached in `summaries.json` (owner-only). Jev labels "info"/"grades" below 0.6 confidence are ignored, so the item stays on the board (a 240-label audit found 32% of those answers wrong, against under 2% above). PDF dates more than 270 days from today are dropped (chart axes, cited years).
  - Microsoft (verified 2026-10-28): MBZUAI's tenant (`c93272d3-…`, managed accounts) blocks students from registering apps (Entra "You do not have access", 401), so Microsoft Graph (Outlook mail, Teams) needs IT to register the app or grant consent. Outlook **Calendar** works without that: the user's calendar is published (Outlook ▸ Settings ▸ Calendar ▸ Shared calendars), and `Outlook.swift` reads its ICS link. The link is a secret, kept in the Keychain under account `outlook.ics` and never logged. One-off events join the course they name, else GENERAL, as `CourseEvent.Source.outlook`; recurring class sessions (the timetable, 18 of 56 events) stay off the board. TZID times are read as the Mac's time zone. The sidebar's **Calendar** page (`CalendarView.swift`, route `.calendar`, ⌘L; sits above COURSES) shows every session from `store.calendarItems`. `OutlookCalendar.occurrences` expands WEEKLY and DAILY RRULEs (INTERVAL, BYDAY, UNTIL, COUNT), skips EXDATEs, and shows a moved session (RECURRENCE-ID with the same UID) at its new time. Only the main "Calendar" is published; the user's second calendar "Robo Plan" isn't (as of 2026-10-28). MBZUAI classes run Monday to Friday, so an empty weekend is correct.
  - School mail (verified 2026-10-28): Outlook forwarding (Settings ▸ Mail ▸ Forwarding, "keep a copy" on) sends school mail, including Teams message notifications, to the user's Gmail. `SchoolMail.swift` reads it over IMAP by running `/usr/bin/curl` (imaps, `[Gmail]/All Mail`, `UID SEARCH SINCE … TO "mbzuai.ac.ae"`). The Gmail app password is in the Keychain under account `imap.gmail.com` and is passed to curl in a `-K -` config on stdin, never as an argument. MIME parsing handles multipart, base64, quoted-printable and the declared charset (windows-1252 subjects showed "�" when read as UTF-8). Messages are cached by UID in `mail.json` (owner-only, last 60 days), become `.outlook` announcements routed like Moodle messages, and their dates go on the board. New mail posts a notification after the first download. Forwarding only applies to mail that arrives after it is enabled.
  - Live mode: the app syncs every 5 min, keeps running with no window (`AppDelegate`), has a `MenuBarExtra`, registers as a login item (`SMAppService.mainApp`), and posts macOS notifications for what changed since the previous sync (`Notifier.changes`, never on the first sync). To test, delete an announcement from `moodle-cache.json` and relaunch.
  - Keychain: every rebuild changes the ad-hoc signature, so macOS asks for the Mac login password ("Always Allow") on the next launch. A separately built binary can't read the item, so run `--moodle-check` from inside the app bundle after allowing it; otherwise it prints "no key stored".
  - Look: always dark, "terminal" theme. Tokens are `Tech.*` in `Theme.swift`; shared motion and panels live in `Effects.swift` (`techPanel`, `stagger`, `pulse`, `SectionLabel`, `TypewriterTitle`, `TechBackground`). Continuous animations must respect Reduce Motion.
  - Responsive layout: decide breakpoints from a `GeometryReader` (the width the pane is offered). Measuring your own content (`onGeometryChange` on the content) feeds back: a wide layout props the pane open, and narrow windows then overflow.
  - macOS gotchas: `Slider(step:)` draws a tick mark per step, so round in the binding instead. `List(selection:)` forces the system-blue highlight, which is why the sidebar uses buttons; the Go menu has ⌘0 Overview, ⌘D Deadlines (week board), ⌘1… courses, ⌘R sync.
  - Data flows through `Store` (sample until connected). The week board (`WeekView.swift` + `WeekBoardParts.swift`) uses `deadlines()` from `Model.swift` and the shared `weekStart(of:)`; `crunch()` is pure and self-checked.
  - Sample data and grade math are a Swift port (`macos/Sources/AcademicAssistant/Model.swift`) of `lib/dashboard.ts`. Keep the two in sync until real data arrives.
