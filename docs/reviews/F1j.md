## Focus answers

1. **Old board-state PDF marks:** fixed. `pruneMarks(..., keepPDF:)` now keeps `pdf != false` (`BoardState.swift:50-52`), so a Mark decoded from a pre-F1h file (`pdf == nil`) is treated as possibly PDF and survives an unreadable-PDF run; new non-PDF marks are written with `pdf = false` (`Store.swift:89`) and are not over-kept. The old-JSON test (“a board-state file without the pdf flag still decodes, and such a mark survives an unreadable PDF”) passes.
2. **Relative-word positions:** the main cases are fixed. `relativeWord` collects every relative word with its position, also when absolute dates exist; after a cue, relatives at/after `cueEnd` are added, so “move today's office hours to tomorrow”, “Quiz Tuesday moved to Thursday” and “Quiz on 20 Oct moved to Thursday” give the new day and `moved = true`; “today's quiz is moved to room 3” keeps today with `moved = nil`; the second net now ignores an invalid post-cue date (`real`, `Moodle.swift:676-681`), so “moved to 31 Feb” no longer deletes the old date. **Gap:** `relativeWord` matches only full weekday names (`monday…`), while `moveCue` accepts `mon|tue|thu…`; a post “moved to Thu” matches the cue but yields no Thursday, so an old date stays (second net) and `moved` is nil. The test only exercises the regex, not a date event.
3. **Ranges:** the code now suppresses range endpoints unless `ranges: true`, and `Model.swift:618` passes `ranges: [.coursePage, .pdf].contains(...)`; `namedDays` additionally checks a ≤7-day span (using year 2001 and a year roll for “30 Dec – 2 Jan”). The compact forms behave: a news “Dec 1-2” with `ranges: false` gives only Dec 1 (test), and page/PDF ranges give both days. **Caveat:** the F1j test “moved from 1 Oct to 15 Dec, ranges:false == [10/1, 12/15]” does not prove “no range days” — both dates are explicit `dayMonth`/`monthDay` hits, so the range union was never needed; the test is weak, though the code is right for the compact case. `onDays` still maps the two endpoints to the nearest year independently, so “30 Dec – 2 Jan” can give `lo > hi` and no range (duplicate, not loss); F1j fixed `namedDays` but not `onDays`.
4. **Per-key PDF lock:** no deadlock found. `parsing` is now `Mutex<[String: NSLock]>`; `entry` takes the per-path lock only after releasing the map lock, then the short `entries` lock inside; lock order is per-key → entries and no path takes entries while waiting for a per-key lock, so no cycle. Different PDFs parse concurrently and the same PDF is parsed once (tests pass). Remaining edges: an **unreadable** PDF stores no negative entry, so a second first-time caller still calls `load()` again; a `load` closure that re-enters `PDFCache.entry` for the same path would self-deadlock on the non-recursive `NSLock` (current loaders do not); a continuous stream of same-file callers can starve a waiter because `NSLock` is not fair; one lock object per path is retained for the run.
5. **`timemodified == 0`:** the new download stamp fixes the first-switch case: a same-size unstamped file from before F1j is re-downloaded once, stamped with the `com.tbaolong45.academicassistant.downloaded` xattr, and then accepted; `isSaved` requires the stamp when Moodle has no timestamp (`Materials.swift:23-35`, `:66-76`). Documented limits remain: after the stamp, a same-size change with no timestamp is missed; a `file.size == 0` file plus stamp accepts **any** local size, so a size change is missed too; a backdated replacement is missed; if `setxattr`/`getxattr` fails (unusual filesystem) the file can be re-downloaded every sync. These are documented/accepted, but the `size == 0` variant is broader than “same size”.

## Findings

1. **Medium — relative weekday abbreviations are still not parsed.** `Moodle.relativeWord` (`:~611`) matches `monday|tuesday|…` only, while `moveCue` accepts `mon|tue|wed|thu|fri|sat|sun`. “The lab shifts to Thu”, “moved to Tue” and “next Mon” match the cue but produce no relative date; with an absolute old date the second net ignores the cue and the old date remains, otherwise no event is created. Add the abbreviations (and make `w` suffix matching use them). The test table only checks the regex, so this is untested.
2. **Low/Medium — the range test for a news post does not prove the range restriction.** `SelfCheck` line ~1361 expects both “1 Oct” and “15 Dec” with `ranges: false`; those are two explicit dates parsed by `dayMonth`/`monthDay`, so the assertion passes whether or not range union is disabled. Add a compact news case (“Dec 1-2”/“1-2 Dec”) that must yield only the first explicit day, and a page/PDF control that yields both.
3. **Low — `onDays` and `namedDays` disagree on year-crossing ranges.** F1j fixed `namedDays`' 30 Dec – 2 Jan roll, but `Model.onDays` still uses `day(r.from)` and `day(r.to)` independently with nearest-year selection; “30 Dec – 2 Jan” can produce `lo > hi` and be treated as no range. Duplicate rather than vanished, but inconsistent with the helper. Use a single reference year and a roll, as `namedDays` does.
4. **Low — the download stamp has two broad limits.** After a `timemodified == 0` file is stamped, any same-size change is missed (documented), but because `file.size == 0` means “any local size”, any size change is missed too; and an xattr failure makes the file re-download every sync. The comment should mention the `size == 0` case, and a fallback stamp (sidecar/mtime) would avoid the xattr-failure loop.
5. **Low — per-key lock edges:** unreadable PDFs double-parse (no negative cache); a re-entrant `load` deadlocks; `NSLock` is unfair (same-file starvation); the lock map grows by path for the run. None affects the current callers; note for future.
6. **Verification — the working tree is not green.** Uncommitted F1k changes in `Moodle.merge`/`Store` make the old P6 merge test fail; F1k's test writer must update that expectation. The F1j/U6 checks pass in the 02:13 binary; no live `--moodle-check` or `--doc-check`.
