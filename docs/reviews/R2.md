# R2 — read-only backend fault hunt

Reviewer: DeepSeek #2 (read-only). Date: 2026-11-02.
Scope (T6 §R2): `Moodle.swift`, `Store.swift`, `SchoolMail.swift`, `Outlook.swift`, `Materials.swift`, `Classifier.swift`, `Summarizer.swift`, `Notifier.swift`, plus the `deadlines()`/`crunch()` path in `Model.swift`/`WeekView.swift`.
Snapshot: files as of ~23:05. The tree moved during the review (B1's board cache landed at 22:53–22:57 in `Store`/`Model`/views), so line numbers are for that snapshot; findings 1–5 are in code B1 did not touch.
Method: code reading plus targeted string/regex checks. I did not run a live sync (no credentials in this session); this is not a reproduced run.

## Findings, most severe first

1. **High — course-page and GENERAL dates are deleted after every sync.** `Store.swift:123`, with `Moodle.swift:193` and `Moodle.swift:249-259`; `Materials.swift:59-78`.
   `applyDocumentDates` drops **every** `source == .document` event and re-adds only what `MaterialStore.documentEvents` found — and that function reads PDFs only. But course-page label/section dates (`Moodle.swift:193`) and the shared university-calendar dates moved to GENERAL (`249-259`) are also `.document`. Scenario: Communication's "Critical Reading Assessment – During Lab 21st October" is on the board only between `apply` and the end of the PDF scan, then disappears until the next sync — i.e. absent ~99% of every 5-minute cycle; the same for the holiday/reading-day entry in GENERAL. The cache can't save it because `MoodleCache.save(result)` stores the raw sync, and on launch the same apply-then-strip runs again (`Store.swift:44`).
   Fix: give PDF hits their own source/flag (or have `documentEvents` return page events too) and have `applyDocumentDates` remove only its own kind.

2. **Medium — Disconnect does not stop in-flight merges; real mail/calendar is merged into sample data.** `Store.swift:91-92`, `190`, `212`, `306-317`.
   The Disconnect button is never disabled (`ConnectView.swift:113`). Scenario: press Disconnect while `sync()` is awaiting `addSchoolMail` (IMAP search + up to 200 fetches can take seconds); `disconnect()` sets `subjects = Subject.all` and `isConnected = false`, then the awaited `addSchoolMail` resumes and runs `subjects = … SchoolMail.merge(mail, into: subjects)` at line 212 — the sample dashboard now shows the user's real forwarded mail; `addOutlookCalendar` (190) does the same for real calendar events. There is no `isConnected` re-check after these awaits.
   Fix: generation counter or `guard isConnected` after each await (and cancel the sync task in `disconnect`).

3. **Medium — duplicate deadline cards across sources; mail can even collide on `Deadline.id`.** `Outlook.swift:75-79`, `SchoolMail.swift:167-170`; Moodle dedupes only inside its own result (`Moodle.swift:196-197`).
   The same exam posted on Moodle and added to the Outlook calendar → two cards at the same instant, and the ids differ (`event/announcement/…` vs `event/outlook/…`) so nothing merges them. A Moodle announcement forwarded to Gmail produces a second `.announcement` event with the same timestamp and title — then both `Deadline.id`s are identical, so the week board's `ForEach` sees duplicate ids as well as a duplicate card.
   Fix: one normalisation pass over `s.events` by (date, normalised title) before `deadlines()`, preferring calendar/Outlook over a mentioned date.

4. **Medium — a stale PDF scan overwrites a newer sync.** `Store.swift:112-118`.
   `addDocumentDates` snapshots `subjects`, parses every PDF in a detached task, then applies the result to whatever `subjects` is *then*. Scenario: `sync()` returns (freeing the `syncing` guard) while the scan is still running; ⌘R starts a new sync, which downloads a corrected schedule; the older scan then finishes and replaces the PDF events with the old set (and deletes the fresh course-page events, per finding 1). Fix: pass a generation/version and drop results from an older snapshot, or await the scan inside `sync`.

5. **Low–Medium — "Oct. 20" is never parsed.** `Moodle.swift:460`.
   The text is split on `". "` before matching, so "Submit by Oct. 20." becomes `"Submit by Oct"` + `"20."`; neither part has a month and a day. The `mon\.?` in `monthDay` (`452`) shows this form was meant to work; same for "Sept. 5". Scenario: "Quiz on Oct. 20" — no card at all. Fix: don't split on a period preceded by a 3+ letter month abbreviation, or run the regexes on the unsplit sentence.

6. **Low–Medium — `general` in any text routes to the GENERAL subject.** `Moodle.swift:590-592`.
   `route` does a bare substring test on `code`, and GENERAL's code is `"GENERAL"`. Once a sync has produced a GENERAL subject, any Outlook event titled e.g. "General Chemistry review" or a mail containing "general" is filed under GENERAL instead of the course it names, because the code pass runs before the name pass. Fix: skip the GENERAL subject in `route` (or match codes with word boundaries).

7. **Low — `known` grows without bound.** `Store.swift:24`, `143`; `Classifier.swift:119-123`.
   Each `classify()` adds up to 300 new text hashes and nothing ever removes an entry (courses end, announcements age out, entries stay). `kinds.json` is decoded at launch and rewritten after every run. Fix: prune by age or keep only hashes still referenced by a subject.

8. **Low — `titles` is pruned only while `summarize()` runs.** `Store.swift:176-178`.
   Removing the DeepSeek key (or having no Jev key) makes `summarize()` return at line 155, so `summaries.json` keeps entries for events that no longer exist indefinitely. Fix: prune in a path that runs regardless of keys.

9. **Low — cache save failures are silent.** `Classifier.swift:122`, `Summarizer.swift:149`, `SchoolMail.swift:197`, `Moodle.swift:607` — all `try? writeOwnerOnly(…)`.
   Scenario: disk full or Application Support read-only: the sync looks successful, but the grades cache is not written (next launch silently opens on sample courses until the first successful sync), and every launch re-pays for classification already done. Same `try?` as R1 §6, seen from the data-loss side. Fix: surface it in `warnings`/`classifierNote`.

10. **Low — mail with an unparseable `Date` is dropped with no warning.** `SchoolMail.swift:50`, `140-148`.
    Only three formats are accepted; e.g. `Date: 2 Nov 2026 09:00:00 GST` matches none, `parse` returns nil, and `addSchoolMail` skips it silently (`Store.swift:205`). Fix: count skipped messages into `mailNote`, or accept more formats.

11. **Low — all-day ICS events become 24-hour events starting at 23:59.** `Outlook.swift:53-56`, `98`.
    DTSTART and the exclusive DTEND are both mapped to 23:59 of their day, so the occurrence runs 23:59→23:59 (+24 h) and spills into the next day on the Calendar page. The 23:59 board date is intended; the calendar duration is not. Fix: treat `VALUE=DATE` as all-day (end = start of next day) for `Occurrence`, keeping the board at end-of-day.

12. **Low — a fraction in prose becomes a date.** `Moodle.swift:484-488`.
    In non-strict text, `3/4` is accepted unless the sentence has a grade word; "About 3/4 of you will…" creates a 3 April event. Fix: require a year or a nearby date word for numeric dates in announcements, or reject when followed by "of".

13. **Low — a late-December date in an early-January post lands a year ahead.** `Moodle.swift:531`.
    The year only rolls forward when the computed date is more than 30 days in the past; a post on 5 Jan saying "the final was Dec 25" resolves to 25 Dec of the *new* year. Fix: also roll back when the date is more than ~300 days ahead.

14. **Low — curl's stderr is piped but never drained.** `SchoolMail.swift:22-31`.
    `errors` has no reader; if curl ever writes more than the pipe buffer to stderr it blocks writing, `readDataToEndOfFile` never returns, `sync()` never finishes and `syncing` stays true (no further syncs, no error). `-s` makes this unlikely; the failure mode is a permanent hang. Fix: send stderr to `/dev/null` or read it concurrently.

## Minor (not worth an item on their own)
- `Outlook.swift:17` `Occurrence.id` is `title|start`, so two same-title sessions at the same minute collide as SwiftUI ids.
- `Store.swift:292-303` `connect` never deletes the previous site's Keychain token (a stale secret survives a site switch).
- `Materials.swift:25-28` files removed from Moodle are never deleted from `~/Documents/Academic Assistant`.
- `Moodle.swift:523-526` can inherit a clock time from an unrelated following sentence ("Quiz due Oct 20. Doors open 09:00." → the quiz becomes 09:00).

No new secret leak found in these paths: Moodle network/server errors are redacted in `call`/`error`, IMAP credentials stay on curl's stdin, and the Outlook/mail notes carry only static `LocalizedError` text or `localizedDescription` (the link/password are not in it).
