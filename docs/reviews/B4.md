## Focus answer — can two different real deadlines merge?

**Yes, in three cases the four guards do not cover.** The guards work for what they were written for, but none of them requires that two mentions of the *same source kind* have the same `ref`; an exact title within 3 days is enough.

1. **Medium — two one-off calendar events with the same title merge.** `same` (`Model.swift:580-596`) skips the ref check unless the two refs are *equal* (`if let r = a.ref, r == b.ref, a.date != b.date`), then the exact-title fast path returns true. Two **Moodle calendar** events "Seminar" on 20 Oct (ref 41) and 22 Oct (ref 42), or two **Outlook** events "Career Fair" with different UIDs, are different events but become one card; the first date and one of the two titles are lost. The new tests cover Quiz 3/4 and Assignment 1/10 (numbers) and two activities, but not two same-titled calendar/Outlook items. Fix: if both members are `moodleCalendar` or both `outlookCalendar` and both refs are present and different, do not merge (a move cue can still allow it).
2. **Medium — the function-word skip list removes the words that distinguish two class changes.** `clusterSkip` (`Model.swift:548-553`) drops weekdays, "today/tomorrow", "moved/postponed/…", "week", "next", etc. `clusterWords("Class moved to Tuesday")` and `"Class moved to Thursday"` both become `{class}`; numbers are empty; titles are not exact but the shared-word threshold is `max(1, min(2, 1, 1)) = 1`, so they merge within 3 days. The same happens for "No classes on Monday" / "No classes on Tuesday" (both Jev `classChange`). Those are two different cancellations; one disappears. The tests assert the skip words are harmless for the moved TED/Presentation cases but never check two titles that differ only in a skipped weekday. Fix: don't strip weekdays from the *identity* set (strip them only from the move-cue sentence), or require a shared non-generic word/number before merging two `classChange`/event items.
3. **Low — the same-ref guard is pairwise, not cluster-wide.** `same` refuses A/C if they share a ref and differ in date, but a bridging B (no ref, title/words matching both, dates within 3 days of each) can union A–B and B–C, and the cluster-level guard checks only activity and numbers, not refs (`cluster`, `:565-612`). A "Final Presentation" row on 27 Oct and another on 6 Nov from one schedule PDF, with a news mention on 1 Nov, can end up in one cluster and lose a row. Fix: keep a per-cluster `ref → date` map and refuse a union that would put one ref at two dates.
4. **Low (deviation, conservative) — a Jev `class_change` label does not open the 30-day window.** `movedAfter` requires `items[m].moved == true` (`:577-579`); `CourseEvent.moved` is set only by the regex, while `isMoved` (used for the winner's date) also includes `kind == .classChange`. §2.3 says the Jev label counts as moved, so a genuine class change whose wording the regex misses stays a duplicate (not a vanished card). The new test codifies this ("a Jev classChange label alone doesn't open the 30-day window"). Acceptable under "duplicate is better than vanished", but it is a spec deviation to record.

## Date and weight winner rules
- **Winner (title/kind/click):** highest `resolvedVia.rank`, then newest `posted` (`merge`, `:617-640`); nil `posted` sorts as oldest. The TED test picks the Moodle title, and the rank table matches §2.1. ✓
- **Date:** if the winner is a Moodle activity, its date stays; a moved member more than 12 h away becomes `conflict` "Post on … says moved to …" (D3), shown on the card/preview with a triangle icon and read by VoiceOver (`WeekBoardParts.swift` conflict note / `spoken`). Otherwise the newest `posted` moved member's date wins. Tests cover both. ✓
- **Weight:** the minimum `order` among the winner and `alsoIn` (Moodle 0, syllabus 1, spare 2, title 3, typical 4), so a PDF "(14%)" gives a weightless activity 14 (test) and a Moodle weight beats a title. `alsoMentioned` and `alsoIn` populate the preview. ✓
- **Open test gap:** no checks for a non-activity winner taking a moved date, multiple moved members, the 12 h conflict threshold, `posted` tie-breaking, or the weight order across several members; add those when the builder next touches the cluster.
