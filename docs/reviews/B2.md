## Findings

1. **Medium — the edited `posted` date is stored but not used when relative dates are resolved.** `Moodle.swift:188` (teacher news), `:217` (messages/notifications), `:262` (site news) all call `Moodle.mentionedDates(..., posted: a.date, ...)`; `a.posted` (`max(created, modified)`) is only copied onto the event afterwards (`CourseEvent.posted`). Scenario: a teacher posts "Quiz on Tuesday" on 1 Oct, then edits the post on 5 Oct to say "moved to tomorrow"; the event date is resolved against 1 Oct (2 Oct) instead of the edit (6 Oct), and the card is wrong even though its `posted` is right. B2 exists partly so an edited deadline wins (backend M5); the date it supplies is still the old one.
   Fix: pass `a.posted` wherever an `Announcement` is the source (`:188`, `:217`, `:262`) and set `posted` from the same value. `SchoolMail` (`SchoolMail.swift:215`) and course-page materials are unaffected (no `modified`).
   The B2 tests check the `Announcement` fields but not this resolution, so it is untested.

2. **Low — the old-cache fallback for mail differs from the spec text (harmless).** `Origin.inferred` (`Model.swift:95-103`) maps old `.announcement` events whose `origin` starts with `✉︎` to `.mail`; the design says old mail *and* message events map to `.news`. Both are rank 4 (same tier), so ranking and filters are unchanged; only a pre-B2 mail event's `memberKey` says `mail` instead of `news` until its first sync. No action needed, but note the deviation.

3. **Low — the ordinal can move when a same-keyword item is added or removed.** `memberKeys` (`Model.swift:109-121`) counts `/n` over all of a subject's events, including events later filtered out by `hasContent`/`sameItem` in `deadlines()`. Identity is date-free as required, but if a hidden same-keyword date appears/disappears (e.g. a bare "Dec 8 — -" line), the visible items' `/n` can shift and B5 marks keyed to the old ordinal would not follow. By design the ordinal is positional, so this is acceptable until B5 defines mark migration; flag it for that step.

4. **Low (tests) — no fixture for the ref-keyed identities (`c:`/`o:`) or for `Deadline.memberKey`.** The B2 checks cover text keys only. Add a Moodle calendar event (`ref: "41"` → `c:41`) and an Outlook item (UID → `o:…`), plus one assertion that `deadlines()` puts the same key on the produced `Deadline`.
