## Findings

1. **Low — toggling Reduce Motion off while a staggered view is on screen can hide it.** `Effects.swift:35-49`.
   With Reduce Motion on, `shown` stays `false` (the guard returns before setting it), and the body renders visible only because of `reduceMotion`. If the user then turns Reduce Motion off, the body re-evaluates with `shown == false` → `opacity(0)` and the 10 pt offset, and `onAppear` does not run again, so the content stays invisible until the view is recreated. Scenario: accessibility setting changed while Overview/Deadlines is open. Fix: add `.onChange(of: reduceMotion) { if $1 { shown = true } }`, or set `shown = true` without animation when Reduce Motion is on in `onAppear`.

2. **Low — the three names the step says to delete are still defined.** `Effects.swift:17-19` (`pulse` no-op), `:66-69` (`TechBackground`), `:71-80` (`TypewriterTitle`).
   The *effects* are gone (plain background, plain title, no pulse), so the CPU reason for the step is met, but the spec says "Delete `TechBackground`, `TypewriterTitle` and `Pulse`". Callers in `App.swift:134`, `HomeView:53`, `WeekView:71`, `CalendarView:46`, `ConnectView:32`, `CourseView:67` still use them, and U2 owns only `Effects.swift`, so deleting them here would not compile. Keep them as shells for now, but they must be removed with their callers (U3 removes `TechBackground`'s caller, U4/U5 the titles, U6 the rest); otherwise the old names outlive the terminal look. A visible consequence today: `TypewriterTitle` still receives the literal `"> deadlines"` / `"> academic_assistant"` strings, so the terminal prompt remains on screen until U4 despite the "terminal look goes" decision.

3. **Low — `techPanel`'s default radius is 10, while the Campus card is 12.** `Effects.swift:12` vs `:9`.
   Callers that pass no radius (`.techPanel()` in `HomeView:110`, `ConnectView:99`, `ScoreChart:69`/`:289`, `WeekBoardParts:305`, `WhatIfPanel:48`) get 10 pt corners; `card()` gets 12. The card style therefore isn't uniform until U4/U5 replace those calls. Make the alias default 12 (its other callers pass 6/8 explicitly) so the transitional builds already match the design.

4. **Nit — sentence-casing a label mangles acronyms.** `Effects.swift:55`.
   The first-character uppercase turns the callers' lowercase strings into "Ai classifier · jev" (`ConnectView:129`) and "Ai titles · deepseek" (`ConnectView:217`), and would do the same for any future "AI"/"KPI" label. Either pass display-cased text from the call sites (U5) or special-case all-caps words; not a U2 blocker.

5. **Nit — `pulse` is now silent, so urgency stops being signalled at all until U4.** `Effects.swift:17-19`; callers at `ConnectView:294`, `CourseView:221`, `HomeView:60`/`:142`, `WeekBoardParts:298` still pass urgency colours into a no-op. The design replaces the ring with an icon + label ("Overdue", etc.) in U4/U5; until then those rows lose their emphasis. Worth keeping on the U4 checklist rather than treating it as a U2 defect.

## Checked and correct

Shadow only in light mode, 6 % black at y 1 (`:30`); "radius 3" is the SwiftUI equivalent of the design's blur 6, as the comment says. Dark mode separates by fill.
- `techPanel` is a thin alias to `card`, so `active:` and `radius:` behave identically; `glow:` is accepted and ignored (glows are gone) — all existing call sites keep compiling.
- Stand-ins cannot break callers: `techPanel` keeps the `active:`/`glow:`/`radius:` labels (glow ignored), `pulse` still returns `some View` and keeps `active:`/`color:`, `SectionLabel` keeps both `text:` and `init(_:)`, and `TechBackground`/`TypewriterTitle` keep their exact initialisers. The 23:28 build compiles every existing call site unchanged, so U3–U6 can migrate one file at a time and delete the shells at the end.
- `stagger` is a one-shot fade + 10 pt rise with a spring and an index-based delay; the old blur is gone and Reduce Motion shows the content immediately (`:35-49`). No repeating animation remains in the file.
