## Findings, most severe first

1. **Medium — a normally spaced phone number escapes the scrub.** `Classifier.swift:144`.
   The separator run is capped at 2 characters (`[ .\-()]{0,2}`), so `050 - 123 - 4567` (space–hyphen–space, 3 chars) does not match. Scenario: an announcement or syllabus line "Call the lab on 050 - 123 - 4567" reaches TypeSafe in `Jev.body` (and can reach DeepSeek through a summarized part) unchanged. The rule text ("digits separated by spaces, `-`, `.` or `()`") covers this format; only the compact form is tested. Verified by running the exact regex: input unchanged.

2. **Low–Medium — the phone rule eats UAE-style dotted dates.** `Classifier.swift:144`.
   `23.10.2026-25.10.2026` and `23.10.2026 10.00` both become `[phone]` (≥9 digits joined by `.`/`-`/spaces). Scenario: a schedule line "Project window 23.10.2026-25.10.2026" is sent to DeepSeek as "Project window [phone]", so the title can no longer state when; Jev's "does it say when" check then fails and the item keeps its plain headline. The board date itself is extracted before scrubbing. The spec protects dates but only the slash form is tested. Verified by running the regex.

3. **Low–Medium — CRLF defeats the signature cut.** `Classifier.swift:130-137`.
   `components(separatedBy: "\n")` leaves a trailing `\r`, and `.whitespaces` does not contain CR (it is in `.newlines`), so `"Best regards,\r"` never equals the sign-off. Verified: trimming leaves `"Best regards,\r"`. Scenario: a Moodle announcement or PDF passage with `\r\n` line endings (`Moodle.plainText` does not normalise CRLF; mail bodies are normalised by `SchoolMail.split`) sends the name and title below the sign-off to Jev/DeepSeek. Emails/phones in that block are still scrubbed; the leak is the name/title.

4. **Low — a signature split across DeepSeek parts leaks its remainder.** `Summarizer.swift:39`.
   `parts` are scrubbed one at a time. If Jev picks "Best regards," as a part it is dropped, but a following part "Dr. Jane Doe" is scrubbed in isolation and sent as its own `- Dr. Jane Doe` line. Precondition is Jev scoring the sign-off sentence ≥ 0.5, so unlikely; the rule is per-text, not per-sentence.

5. **Low — the new `yesNo` scrub has no self-check.** `SelfCheck.swift:349-373`.
   Tests cover `Jev.body` and `DeepSeek.body`, but nothing exercises `Jev.yesNo` — neither the String state in `summarize` nor the dictionary state/questions in `check`. A regression there (including breaking the `[String: String] as? [String: Any]` cast, which would skip the dict branch) would still print "All checks passed". I confirmed the cast succeeds at runtime with a scratch compile, so the code is live today; the gap is in T2.

6. **Low — the caches swallow a chmod failure.** `Classifier.swift:122`, `Summarizer.swift:149`, `SchoolMail.swift:197`, `Moodle.swift:605`.
   `try? writeOwnerOnly(...)` hides an error from the final `setAttributes(.posixPermissions, 0o600)`: the data is already on disk, so the caller reports success. The 0700 folder set before the write still blocks other users, so this is defence-in-depth rather than an exposure — but it is silent.

7. **Nit — `MailError.badCredential` wording.** `SchoolMail.swift:204`. An empty address/password is rejected by the same guard, but the message only mentions "a line break or other control character"; the user gets a misleading reason.

No CLAUDE.md departures found (pure functions, no `@State`, checks in `SelfCheck.swift`, no new logging, no secret in an error string).
