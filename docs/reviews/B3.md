## Findings

1. **High (verification/blocker) — B3 has no test-writer checks at all.** The commit touches `Model`, `Moodle`, `WeekView`, `WeekBoardParts` but not `SelfCheck.swift`. None of the required cases are covered: the §1.5 priority table, Moodle-vs-syllabus-vs-title weight order, the spare 7.5, the exact reason strings, the 28-day horizon, `effective` (extension earlier/later, cutoff 0) or the cutoff reason. The self-check being green therefore says nothing about B3 and the step's done criterion ("including the test writer's B3 checks") is unmet.

2. **Medium — "Final Paper" is typed as a final, which distorts Do next (focus 3).** `Ranking.textType` (`Model.swift:343-346`) uses `Moodle.kind(nil, title)`, whose "final" branch matches "Final Paper"; `typicalWeight(.final)` is 30 and `effortHours(.final)` is 15 (`:312-331`).
   - With a title percentage ("Critical Writing - Final Paper - 14%"): weighting is 14 from the title (correct), but effort is 15 h. The design's own §1.5 real-case row expects **7 h and priority 1.51** (assignment effort, 0.5 h per %); the code gives `slack = 11.6 − 5 = 6.6` and `priority = 14/6.6 ≈ 2.12`, so the item ranks above the 7.5% quiz and its reason says "~15 h" instead of "~7 h".
   - With no percentage (a text event, or a Moodle item with weight 0): it falls through to the **typical** weighting — "~30% est.", 15 h — and can rank above real items; on a Moodle assessment it also gets `kind == .exam`, so Do next and crunch treat a paper as a final exam.
   - **Crunch** does *not* get the 30% estimate: it still sums `Deadline.weight` (`WeekView.swift:29`, `Crunch.weight`), which for a text item is `percentInTitle` (nil) and for a weightless assessment is 0. So the distortion is in Do next/reason/ranking, while the card shows "0%" or no tag and the reason says "~30% est."; a 3-item crunch can still be triggered by it as an exam.
   - Fix: infer a type for text only from explicit exam phrases ("final exam", "final test"), or use the Moodle module/assessment type for Moodle items instead of the name; keep "Final Paper" as an assignment/other with 0.5 h per %.

3. **Medium — crunch still counts CLOSED items.** `WeekView.swift:29` filters `date >= now && (toSubmit || kind == .exam)` but not `!$0.isClosed(now:)`. A past-cut-off assignment is shown as "Closed" (`WeekBoardParts.swift:137`) and leaves Do next (`doNext`, `Model.swift:413-420`), but it still feeds the crunch's item count/weight, producing a crunch banner for work Moodle no longer accepts. Add the `isClosed` guard (and decide whether a closed item stays in the week's workload at all).

4. **Low — `Deadline.weight` and `Deadline.weighting` diverge.** Cards tag `d.weight` and crunch sums it; Do next/reason use `weighting` (Moodle → syllabus → spare → title → typical). A typical-weight item shows "~5% est." in the reason but no tag (or "0%" for a weightless assessment), and a spare shows "7.5% if it counts" while the tag is nil; estimates never affect crunch. This is self-consistent only until B5/B6 display the estimate; either store `weightIsEstimate` (planned in §5) and use it in the tag/crunch, or document that crunch is known-weight-only.

5. **Low — overdue Moodle assignments with no cutoff stay in Do next forever** (`doNext` keeps `toSubmit && resolvedVia == .moodleActivity` before `now`; `isClosed` false with cutoff nil). This is what check (h) asks for, but in real use old open work can occupy the top three and hide fresh items; B6's filters/"hide overdue" or a cutoff convention should own that.

6. **Low — an extension is lost when the per-assignment status call fails.** `extensions` is only populated for assignments whose `mod_assign_get_submission_status` succeeded (`Moodle.swift:143-150`); on a failure the sync carries a warning and the extension/cutoff for that assignment is missing that run (status falls back to dates/grades). Acceptable per the warning design; note for the live check.

7. **Low — cutoff/extension on a graded assessment depends on a name match.** `deadlines()` finds `s.assignments.first { sameItem($0.title, a.name) }` (`Model.swift:466-471`); if the assignment title and grade-item name diverge, the assessment keeps no cutoff/extended even though `AssignmentItem` has them. It affects the "Closed" tag/reason, not the assignment card.

## Checked and correct
- **Effective due before gradebook dates:** `Moodle.swift:174-183` maps `courseAssigns` through `effective` **before** `assessments`, `assignmentItems` and `briefs`; the gradebook item's `assign#id` date is therefore the effective due. `effective` (`:419-427`) does `duedate = max(duedate, extension)`, `extended = extension > duedate`, `cutoff = max(cutoff, extension)` when cutoff > 0; extension 0 and a missing cutoff leave the date alone. `Assign.cutoffdate` and `Attempt.extensionduedate` are optional, so old API replies decode; `AssignmentItem.cutoff/extended` are added (`Model.swift:50-51`).
- **Priority formula:** `priority = weighting.value / max(slack, 0.25)`, `slack = daysLeft − effort/3`, `startBy = due − effort/3` (`Model.swift:355-363`); weighting order Moodle > syllabus > spare > title > typical (`:334-340`); effort table matches §1.1 (`:322-331`), including project `max(6,w)` and assignment `clamp(0.5w,2,12)`; spare uses `total / best` from the first matching syllabus part (`:348-352`).
- **Sample §1.5 rows** evaluate correctly by the formulas: LA Assignment 2 48.0, AI Midterm 37.5, Problem sheet 7 20.0, Python Assignment 2 3.0, Reading 2.3, Code review 1.6, Lab 3 1.5, LA Final 0.93; Do next = Assignment 2, Midterm, Problem sheet. (No fixture asserts them — finding 1.)
- **Reason lines** (`Model.swift:366-399`): percentage/spare/estimate text, "due in N days"/"due tomorrow"/"exam in N days", "(extended)", "late until <weekday day month>" before the cutoff, "closed" past it, "behind by ~N day(s)" when slack < 0, and "→ start today"/"start by <date>" otherwise; the `Date.VerbatimFormatStyle` uses an en-US POSIX weekday/day/month and the current calendar's time zone. Matches §1.3's examples for the 12%, 8% and slack-negative cases.
- **Do next** (`Model.swift:413-420`): top 3 among `toSubmit` or `.exam`, due inside 28 days, not closed, future items plus overdue Moodle assignments until their cutoff, priority then date; `WeekView.swift:19-20` now calls it; exams are included (D2).
- **WeekBoardParts:** CLOSED tag after PAST/OVERDUE logic, the Do next chip's second line is `reason(now:)`, the preview shows the reason and `weightNote`, and the chip's accessibility label includes the reason (`WeekBoardParts.swift:136-200`, `:236-246`).
