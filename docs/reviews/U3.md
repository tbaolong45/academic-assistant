## Findings

1. **High (verification/blocker) — the tree is not green and the app bundle is stale.** The committed `--self-check` fails the two old mail tests, so `./macos/build-app.sh` (which runs `--self-check`) cannot pass; U3's done criterion is therefore not demonstrated. Separately, `build/Academic Assistant.app` was assembled at 23:51, before the U3 edits (23:55–57), so the bundle does not contain this step at all. The failures are F1b test lag, not U3 code, but the commit cannot be called green.

2. **Medium — the bundle still declares macOS 15.0.** `macos/Resources/Info.plist` has `LSMinimumSystemVersion = 15.0` (the copied `build/.../Info.plist` shows the same) while `Package.swift` now targets `.macOS(.v26)`. The Mach-O built by Swift 6.2 will require macOS 26, but LaunchServices will let the bundle install/launch on 15 and dyld will reject it. Raise `Resources/Info.plist` to `26.0` (and any other deployment metadata in the script) in this step, since it is part of the target raise D3.

3. **Low — "use `Palette.bg` as the window background" is indirect.** The detail pane still uses `TechBackground()` (`App.swift:130`), whose body is `Palette.bg.color.ignoresSafeArea()`; the sidebar now correctly uses the native material (no `.background(Tech.panel)`/`.scrollContentBackground(.hidden)`). Visually this is the Campus canvas, but the spec asks for the token and the transitional wrapper is meant to disappear at U6. Replacing `TechBackground()` with `Palette.bg.color.ignoresSafeArea()` (and removing the wrapper at U6) makes the step literal and avoids the sidebar material sampling a different window fill. No defect today; check it in both appearances.

4. **Low — system appearance is now reachable but nothing verifies it.** Removing `.preferredColorScheme(.dark)` exposes every screen to light mode; the U1 palette passes its numeric contrast checks, but several screens still carry terminal-era fragments until U4/U5 — e.g. `WeekBoardParts.swift:284` still sets `.fontDesign(.monospaced)`, `HomeView` still has the "SYNCED" tracking and two 1 s `TimelineView`s, and `ScoreChart` still tints with `Tech.neon`. Those are scheduled, not U3 defects, but the U3 acceptance ("follows the system") needs a manual light-mode pass over Overview/Deadlines/course/Connect; there is no automated UI check.

5. **Nit — sidebar section header casing/style.** `Section { … } header: { Text("Courses") }` uses the native list header, while page sections use `SectionLabel` (`.title3.semibold`). Not required by U3, but it will read inconsistently until U4/U5 decide the sidebar header style.

## Checked and correct

- `.tint(Palette.accent.color)` is set once on `RootView`, so controls/sheets inherit the Campus blue; `Palette.onAccent` is white at 5.17/4.65 (existing U1 check).
- Sidebar keeps the button rows (no `List(selection:)`), now with a native material; selected row = `accentSoft` pill + `accentInk` text + semibold (contrast 6.07/6.19 from U1), hover = `raised` at 0.7, course dots are 8 pt `mark` colours with no glow, and the neon bar/shadow/offset are gone. `.navigationSplitViewColumnWidth(min: 220, ideal: 260, max: 340)` matches the spec's narrowed sidebar.
- Accessibility: rows combine children and add `.isSelected` only for the selected row; icons no longer rely on colour alone; the course dot keeps the name beside it.
- `Package.swift`: `swift-tools-version: 6.2`, `platforms: [.macOS(.v26)]`; the 23:57 release build compiles with it. No `#available` branches are needed for the APIs currently used.
- `HomeView`'s single-line change (`Text("\(Text(label)…)\(Text(type)…)")`) preserves the bold label + secondary type runs and compiles under the new toolchain; it does not alter the content.
- The remaining `Tech` alias and `TypewriterTitle`/`TechBackground` shells are intentional until U4–U6.
