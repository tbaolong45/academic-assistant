## Findings

1. **Low — the sync status is a coloured dot with a label but no icon.** `HomeView.swift:71-78`. `Sync failed` is a `Palette.critical` dot next to the text, `Synced` a `Palette.good` dot; there is no SF Symbol, unlike Crunch/Heavy/Overdue, which pair an icon with their label. Nothing is colour-only (the text always says the state), but it breaks the rule as written ("status colours always sit next to an icon and a label"). Use a small `checkmark.circle` / `exclamationmark.triangle` (hidden from VoiceOver, label unchanged) or make the dot neutral.
   Related nit in the same tuple: when `isConnected` is true, `lastSynced` is nil and there is no error or sync running, the text is "Not synced yet" but the colour is `Palette.good`; that state should use `text3`.

2. **Low — the crunch banner's amber wash is drawn behind an opaque card and is invisible.** `WeekBoardParts.swift:285-303`: `.card()` applies the `surface` background first, then `.background(amber.opacity(0.12), in: RoundedRectangle(...))` is placed *behind* the whole card, so the opaque surface hides it; only the warning edge and the icon show the status. Reorder (a tinted card variant, or the wash inside the card's background before the surface) if the amber body is wanted. The label + icon rule is still met (Crunch + triangle).

3. **Low — the workload bar uses the warning colour without its own label or icon.** `WeekBoardParts.swift:103-116`: a heavy day's bar is `Palette.warning`; the adjacent "Heavy" tag has the triangle and text, so meaning is not colour-only, but the bar itself is a status-coloured mark with no label. Acceptable given the tag; note it against the literal rule.

4. **Nit — two independent 60 s `TimelineView`s remain on Overview** (`HomeView.swift:53` for the greeting/status, `:97` for the next-deadline countdown). U4 explicitly allows 60 s (they are timers, not animations), but they can share one minute tick; no CPU issue expected.

5. **Nit — `WorkloadBar`'s `.animation(.easeOut(duration: 0.4), value: fraction)` and `Press`'s `.animation(..., value: isPressed)`** are one-shot transitions, not loops; fine.
